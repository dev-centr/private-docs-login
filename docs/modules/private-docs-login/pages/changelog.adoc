== 2026-11-25

=== Designed sign-in pages

* Every HTML page the issuer serves (acceptance, chooser, `/github/setup`, and the stop pages, including no verified email) uses one layout and stylesheet with light and dark themes, a responsive column, and copy that says what happened and what to do next.
* The issuer serves its own assets under `/assets/` from both hosts: Space Grotesk (OFL 1.1, Latin subset), the stylesheet, and the Private Docs Login mark, which is also the favicon. Nothing loads from a font CDN.
* Pages carry a strict Content-Security-Policy (no inline script or style), `Referrer-Policy: no-referrer`, and `X-Content-Type-Options: nosniff`. The GitHub manifest page no longer uses an inline script.
* `/github/setup` shows the installation id and setup action GitHub sends (validated), and the Cloudflare Access values for this issuer.
* `npm run preview` opens every page locally with a stand-in forge. Version 0.3.0.
* Detail: xref:changelog-details/2026-11-25 - designed-pages.adoc[Designed sign-in pages].

=== Token endpoint accepts HTTP Basic

* `/token` accepts `client_secret_basic` as well as `client_secret_post`. Discovery lists both. The Basic credentials are decoded as RFC 6749 section 2.3.1 says (form-urlencoded, then base64).
* A request that uses both methods, or a body `client_id` that differs from the Basic one, is `invalid_request`. A failed Basic attempt is `401 invalid_client` with `WWW-Authenticate: Basic`.
* Client secrets are compared in constant time for any length.
* Detail: xref:changelog-details/2026-11-25 - token-basic-auth.adoc[Token endpoint accepts HTTP Basic].

=== Persistent sign-in state and the Worker host

* Sign-in state (pending requests, one-time codes, access tokens) goes through one async storage interface. Tests use memory. The Node host keeps it in SQLite when `PRIVATE_DOCS_LOGIN_STATE_PATH` is set. The Cloudflare Worker host keeps it in D1. A code is deleted and returned in one statement, so it cannot be redeemed twice. Expired rows are swept on the next write.
* DevCentr's issuer is `https://login.devcentr.org` on Cloudflare Workers, from `deploy/cloudflare/` (`wrangler.toml`, `issuer.sdl`, the D1 migration, and `secrets.mjs`). The Node server stays the reference host. Nothing in `src/` imports a Workers-only module.
* The signing key can be PEM text in `PRIVATE_DOCS_LOGIN_SIGNING_KEY` as well as a file path. `/jwks` also lists `PRIVATE_DOCS_LOGIN_PREVIOUS_JWKS` during a rotation and refuses private key fields there.
* `/healthz` checks the signing key and the state store and answers `503` when either is missing. `/health` stays.
* `/userinfo` no longer extends an access token past its `expires_in`.
* The ID token and `/userinfo` carry `email` and `email_verified` from the verified primary address (GitHub `/user/emails`, GitLab confirmed `/api/v4/user` email). The manifest asks for Email addresses read as well as Organization members read. A reader without a verified primary address is refused with a page that says where to verify it. Discovery lists the `email` and `profile` scopes.
* The example config names `dev-centr` as the GitHub App owner and the GitLab owner group. `github-manifest` prints the owner, the GitHub form URL, and the callback and setup URLs, and refuses a missing owner or a plain-http public issuer.
* The package needs Node 22.13 or later and is version 0.2.0.
* xref:roadmap.adoc[Roadmap] notes that a Marketplace listing later needs a privacy policy URL and purchase webhooks.
* Detail: xref:changelog-details/2026-11-25 - persistent-state-and-worker-host.adoc[Persistent sign-in state and the Worker host].

=== Install is the GitHub App

* The README and the how-to start with an organization owner installing the published GitHub App. Running `private-docs-login` is for a person hosting the issuer, from a checkout of this repository.
* The signing-key step says the file is the issuer's private signing key, that the person hosting the issuer creates it, and that `PRIVATE_DOCS_LOGIN_SIGNING_KEY_PATH` is the path to that file.
* Antora has no playbook extension for this login. A static Antora site uses an OpenID Connect client. The hostname guide that exists is Cloudflare Access for static sites.

=== Private Docs Login is the name

* The command is `private-docs-login` (`bin/private-docs-login.mjs`). The npm package name is `@dev-centr/private-docs-login`. Environment names use the `PRIVATE_DOCS_LOGIN_` prefix. The GitHub App and the GitLab application an owner approves are named Private Docs Login.
* At this point the process still accepted `ANTORA_PRIVATE_DOCS_` when the new name was unset. A later change the same day stops reading that prefix. The documented names were already the new ones.
* The GitHub App already registered on github.com keeps its previous display name until someone renames it in that app's GitHub settings. This repository does not call GitHub to rename it.
* Publishing `@dev-centr/private-docs-login` on npm is a later step. The package stays private until then.
