Set these in the process environment or a gitignored file.
Empty names in `.env.example` match this table.

[cols="2,3,1,2,3",options="header"]
|===

The Worker host also needs the D1 binding `PRIVATE_DOCS_LOGIN_STATE`, declared in `deploy/cloudflare/wrangler.toml`.
On the Worker, every name above is a Worker secret, not a process variable.
| Variable | Purpose | Required | If unset | Source

| `PRIVATE_DOCS_LOGIN_CONFIG`
| Path to the SDL config. The default path is `config/issuer.sdl`.
| No
| The serve command looks for `config/issuer.sdl`.
| Local path. Copy `config/issuer.example.sdl`.

| `PRIVATE_DOCS_LOGIN_LISTEN`
| Bind address `host:port`, overriding the config `listen` block.
| No
| The config `listen` block is used (`127.0.0.1` and port `4180` in the example).
| Local process environment.

| `PRIVATE_DOCS_LOGIN_SIGNING_KEY_PATH`
| Path to the issuer's private signing key. The person who hosts the issuer creates the file on that machine. The file format is PKCS#8 PEM. The example config names this variable from `signing-key.pem-path-env`.
| Yes
| The process refuses to start.
| Create the file on the issuer host with `openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048`. Do not commit it. Set the variable to that file's path.

| `PRIVATE_DOCS_LOGIN_SIGNING_KEY`
| The issuer's private signing key as PKCS#8 PEM text, for a host that cannot read files (the Cloudflare Worker). Named by `signing-key.pem-env`. When both are configured, this one wins.
| On the Worker host
| The Worker answers `503` and `/healthz` reports `not-configured`.
| `var/signing.pem`, uploaded by `npm run cf:secrets`. Kept in Bitwarden. See xref:deploy-cloudflare.adoc[Deploy on Cloudflare Workers].

| `PRIVATE_DOCS_LOGIN_PREVIOUS_JWKS`
| Public keys still published in `/jwks` after a signing-key rotation, as a JWKS or a list of JWKs. Named by `signing-key.previous-jwks-env`. A value with private key fields is refused.
| No
| `/jwks` lists the current key only.
| The old `/jwks` body. Not secret. Remove it after the rotation window.

| `PRIVATE_DOCS_LOGIN_STATE_PATH`
| SQLite file for sign-in state on the Node host. Named by `state.sqlite-path-env`. Needs Node 22.13 or later.
| No
| State is in memory, and a restart drops sign-ins in progress.
| A path on the issuer host, for example `var/state.sqlite`. Not secret.

| `PRIVATE_DOCS_LOGIN_ISSUER_URL`
| Issuer URL for `npm run healthz`.
| No
| `npm run healthz` checks `https://login.devcentr.org`.
| Local shell.

| `PRIVATE_DOCS_LOGIN_GITHUB_APP_ID`
| Numeric id of the GitHub App named Private Docs Login.
| Yes, when the `github` block is present
| GitHub sign-in is not available.
| GitHub organization settings, GitHub Apps, after approving the manifest. The setup command writes it under `var/` and does not print the client secret.

| `PRIVATE_DOCS_LOGIN_GITHUB_CLIENT_ID`
| OAuth client id of that GitHub App.
| Yes, when the `github` block is present
| GitHub sign-in is not available.
| Same GitHub App page, or the gitignored `var/github-app.json`.

| `PRIVATE_DOCS_LOGIN_GITHUB_CLIENT_SECRET`
| OAuth client secret of that GitHub App.
| Yes, when the `github` block is present
| GitHub sign-in is not available.
| Shown once at manifest approval. Stored in gitignored `var/github-app.json`.

| `PRIVATE_DOCS_LOGIN_GITLAB_CLIENT_ID`
| Application ID of the GitLab application named Private Docs Login.
| Yes, when a `gitlab` instance block is present
| That GitLab host is not available for sign-in.
| GitLab group Settings, Applications. The `gitlab-setup` command prints the URL.

| `PRIVATE_DOCS_LOGIN_GITLAB_CLIENT_SECRET`
| Secret of that GitLab application.
| Yes, when a `gitlab` instance block is present
| That GitLab host is not available for sign-in.
| GitLab shows it on the application page. Do not commit it.

| `PRIVATE_DOCS_LOGIN_CLIENT_CLOUDFLARE_ACCESS`
| Client secret for the example Cloudflare Access relying party.
| Yes, if that `client` block is kept
| Token requests for client id `cloudflare-access` fail.
| Choose a secret locally and enter the same value in the Access identity provider. The name is the example; a renamed `secret-env` in config uses that name instead.

| `PRIVATE_DOCS_LOGIN_CLIENT_GENERIC`
| Client secret for the example generic relying party.
| Yes, if that `client` block is kept
| Token requests for client id `generic-rp` fail.
| Choose a secret locally and configure the same value on the relying party.
|===
